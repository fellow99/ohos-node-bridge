## 1. 系统用途与目标用户

### 1.1 一句话

本系统是一个**可发布的组件库**，它让一个 HarmonyOS 应用的**自己的进程**里跑起**真正的 Node.js 运行时**（不是 WebView、不是云函数、不是子进程），并把「启动 / 观测 / 载荷 / 环境 / 宿主能力 / 关停」六件事收敛成一套应用开发者可用的接口。

### 1.2 目标用户

| 用户 | 他们要什么 | 本系统给什么 |
|---|---|---|
| **应用开发者**（主用户） | 把 Node 脚本环境嵌进自己的 HarmonyOS 应用（2in1 / 平板），**不碰 C++、ELF 属性、seccomp、线程模型、字符集** | 一个组件库 + 一份运行时投放工具链 + 一条自检通道 |
| **消费方形态（唯一在册）** | 用 Node 在端上起本地服务，再由系统 Web 容器渲染（规划 §6.1） | 只保证「本地服务在端上跑着」，**不参与渲染** |
| **库的评审者/维护者** | 判定一项改动是否越界、是否可验收 | 可证伪的判据（§4）与责任分界（§3） |
| **上架合规责任人** | 证明「包里没有浏览器内核、没有绕过平台控制的组件、第三方许可齐备」 | 红线 G3/G4/G5/G11 的库侧口径 |

### 1.3 非目标（明确不做，规划 §0.3）

1. **不做应用**：不含窗口、Web 容器页面、页面路由、应用图标、包名、签名主体。
2. **不做任何特定上游产品的专用逻辑**：不理解、也不解释特定应用的环境变量或框架语义（C1）。
3. **不做 Android / Linux / macOS 版本**：只服务 HarmonyOS 应用进程内嵌场景。
4. **不做「崩溃后自动重启」**：进程内启动运行时的语义只允许一次，该项被平台封死（C5 / 规划 §5.2）。
5. **不做子进程形态**：平台不支持（规划 §0.3 / §4.5）。
6. **不做后台无限常驻**：普通应用做不到（规划 §0.3）。
7. **v1 不承诺自建运行时**：先用现成产物打通；自建列为可替换的长期项（C7 / 规划 §5.8）。
8. **不做手机（phone）**：只做 2in1 与平板（规划 §1）。

## 2. 核心能力（六个 API 面，规划 §1.1 / §5.3）

| # | API 面 | 必须让调用方做到什么 | 现状 |
|---|---|---|---|
| **F1** | **启动** | 一次性投递启动参数（入口、参数、可写根、环境），拿到「已投递/被拒绝」的结构化结果；**明确知道**运行时是单例且不可重启 | ✅ 部分（投递 + 单例保护 + 结构化结果已有；`waitUntilRunning` 与会话状态细化 ⬜ 规划未实现 Phase 1） |
| **F2** | **观测** | 读到状态机、结构化日志（环形缓冲）、上一次崩溃记录；并能用一条命令在真机上验「服务真的在跑」 | ⚠️ 部分（状态机 ✅、日志文件读回 ✅、自检端点 ✅；日志环与崩溃记录 ⬜ Phase 1） |
| **F3** | **载荷** | 给出「载荷根 + 入口 + 可选归档 + 工作目录 + 环境」，就能跑起一个真实服务端；重复启动**幂等** | ⬜ 规划未实现（Phase 1） |
| **F4** | **环境** | 运行时的 `HOME` / 临时目录落在应用可写沙箱；宿主环境不会污染运行时；应用语义变量由调用方显式传入 | ✅ 部分（沙箱重定向与 `NODE_OPTIONS` 清空 ✅；`env` 选项合并 ⬜ Phase 1） |
| **F5** | **宿主能力桥** | 脚本侧用**稳定的、带超时与上限**的接口回调宿主能力（权限查询、目录选择、外链、通知），未注册的能力**明确报错** | ⚠️ 部分（注册表 + 结构化错误 ✅；线程安全传输、超时、上限 ⬜ Phase 2） |
| **F6** | **关停** | 请求运行时执行应用注册的收尾钩子并等待窗口期；**明确知道**真正的停止只能是进程退出 | ⬜ 规划未实现（Phase 1–2） |

## 3. 系统边界

### 3.1 在范围内

| 域 | 内容 |
|---|---|
| 运行时获取与校验 | 运行时产物的**锁定**（版本 + 摘要 + 许可 + 来源 + 真机验证记录）、**门禁校验**、**幂等投放**、版本矩阵（规划 §5.8 / 附录 G） |
| 运行时的进程内加载 | 以进程内方式加载运行时并启动，且**不与运行时版本耦合**（C7 / 规划 §5.2） |
| 线程与生命周期 | 专用非 UI 线程、单例、幂等保护、失败态语义（不可重启）、关停钩子（规划 §5.2） |
| 载荷分发 | 只读直读为首选；需要可写时用「单个归档 + **由 Node 自己解包**」+ 摘要幂等 marker（C3 / 规划 §5.5） |
| 环境契约 | 沙箱化的家目录与临时目录、清空宿主注入、应用语义变量透传（规划 §5.6） |
| 观测与取证 | 结构化日志（缓冲 + 持久通道）、崩溃结构化记录、端到端自检端点（C6 / 规划 §5.7） |
| 宿主能力桥 | Node → 宿主的**传输层**（线程安全、JSON 载体、超时、上限、未注册即报错）（规划 §5.4） |
| 平台真相上报 | 能力缺口的**如实上报**（不静默降级）（C2 / 规划 §3.2） |
| 分发 | 组件包形态、版本策略、第三方许可清单、接入文档（规划 §7.5 / §9.5） |

### 3.2 不在范围内（归消费方；规划 §0.1 / §6）

窗口与页面 · 系统 Web 容器的加载页/错误页/导航围栏/Cookie 注入 · 鉴权与安全策略 · 目录选择器的产品形态 · 载荷内容与裁剪 · 受限权限（ACL）的申报与 Profile · 上架材料与合规清单 · 后台常驻与长时任务 · 终端（PTY）与版本控制类端侧工具的**产品用途**。

### 3.3 交付边界（一次分发到底含什么）

组件包**必须**包含：公共接口与类型声明、原生引导件的**源码与类型声明**、内置的 Node 侧参考脚本、运行时**锁文件**、运行时**投放/校验工具**。组件包**不得**包含运行时二进制本体（S10 / 规划 §7.5）。

## 4. 功能需求（RFC 2119：MUST / MUST NOT / SHOULD / MAY）

### 4.1 启动与会话（F1）

| 编号 | 级别 | 需求 | 可证伪的验收判据 |
|---|---|---|---|
| FR-OVR-001 | MUST | 在同一个应用进程内启动 Node 运行时；运行时的进程标识等于宿主进程标识 | 自检输出中 `platform` 与 `arch` 为本平台值，`pid` 与宿主进程一致 ✅（规划 §D.8 结论 1） |
| FR-OVR-002 | MUST | 启动必须发生在**非 UI 线程**，启动期间 UI 不得出现输入阻塞 | 真机启动至自检可访问期间无 `APP_INPUT_BLOCK`/ANR 记录（规划 §5.10 ①） |
| FR-OVR-003 | MUST | 同一进程内启动**最多成功一次**；非初始态再次请求启动必须返回**结构化失败**并保留首次原因 | 连续调用两次：第二次返回 `ok=false` 且带有可读原因；进程无断言崩溃（硬约束 ⑥） |
| FR-OVR-004 | MUST NOT | 提供任何「运行期追加/修改启动参数」的接口 | 公共接口清单内不存在追加参数的入口（C4） |
| FR-OVR-005 | MUST NOT | 提供「崩溃后自动重启运行时」的任何路径或暗示 | 失败态接口只提供读日志/读崩溃记录；文档与代码均无重启路径（C5） |
| FR-OVR-006 | MUST | 启动请求返回「已投递」与「被拒绝」必须可区分，且**不等于**「运行时已就绪」 | 返回值语义文档化；就绪判据必须是外部可观测事实（端口/端点），不是返回值（规划 §5.3） |
| FR-OVR-007 | SHOULD | 提供不阻塞 UI 的就绪等待接口（带超时） | 有超时的等待接口存在；超时后状态为失败而非静默（规划 §5.3）⬜ 规划未实现 Phase 1 |
| FR-OVR-008 | MUST | 启动参数在启动前**定死**；诊断用开关（会关闭平台能力的那个）**只能**作为诊断开关出现 | 接口文档明确该开关为诊断专用；产品路径默认不开启（C4 / 规划 §4.7） |

### 4.2 载荷（F3）

| 编号 | 级别 | 需求 | 可证伪的验收判据 |
|---|---|---|---|
| FR-OVR-010 | MUST | 支持「载荷只读直读、零解压」 | 载荷放在只读安装位置，入口能被加载并完成一次真实请求（规划 §5.5 路线① / §5.10 ⑩） |
| FR-OVR-011 | MUST | 若载荷可写则以**单个归档**投递，且解包方必须是 **Node 自己**；禁止用平台侧解压器写业务文件 | 解包出的文件能被 Node **读回**（不是只 `stat`）（C3 / 硬约束 ④） |
| FR-OVR-012 | MUST | 归档解包必须**幂等**：摘要命中即跳过 | 二次启动不重复解包，且耗时显著低于首次；marker 命中可见（规划 §5.5） |
| FR-OVR-013 | MUST | 入口解析必须支持两种模块风格的混用，且入口一律解析为**绝对路径** | CJS 与 ESM 入口各能启动一次（规划 §5.5） |
| FR-OVR-014 | MUST NOT | 依赖进程当前工作目录来拼路径 | 在真机（工作目录为根）下功能完整（S4 / 规划 §D.8 偏差表） |

### 4.3 环境契约（F4）

| 编号 | 级别 | 需求 | 可证伪的验收判据 |
|---|---|---|---|
| FR-OVR-020 | MUST | 家目录与临时目录必须指向应用**可写沙箱** | 自检输出中家目录/临时目录在沙箱内，且临时目录内写-读回一致（规划 §D.8 结论 1） |
| FR-OVR-021 | MUST | 启动前清空宿主注入的运行时参数变量，避免宿主环境污染运行时行为 | 运行时视角的该类变量为空（规划 §5.6 / 旧壳构建期同做法） |
| FR-OVR-022 | MUST | 强制关闭平台**被拒绝的系统调用**探测路径（应返回「不支持」而非让它崩溃） | 启动不因该探测崩溃；探测结果写入日志（规划 §5.10 ③④） |
| FR-OVR-023 | MUST | 应用语义变量**由调用方显式传入**；库不解释、不硬编码任何应用特有变量名 | 组件包内不含任何应用特有变量名的解释逻辑（C1）；原生层已提供通用注入通道 `envPairs` ✅，ArkTS 侧接线 ⬜ ⚠️ 另有 1 处越界（见 §7） |
| FR-OVR-024 | SHOULD | 承载运行时的应用应满足一个**最低运行时版本**；低于该版本必须给出可见告警，不得静默继续 | 低版本场景出现可见告警（C2）⬜ 规划未实现 Phase 1 |
| FR-OVR-025 | MUST NOT | 修改与动态链接搜索路径相关的宿主环境变量 | 启动前后宿主环境该项不变（规划 §5.6） |

### 4.4 观测与崩溃取证（F2）

| 编号 | 级别 | 需求 | 可证伪的验收判据 |
|---|---|---|---|
| FR-OVR-030 | MUST | 同时提供**持久日志通道**与**文件日志**两条通道；关键信息两边都有 | 同一条启动信息在两条通道均可查（S9 / 规划 §5.7） |
| FR-OVR-031 | MUST | 提供**日志读回**能力：日志文件不可读时返回占位说明而不是抛异常 | 故意指向不存在的日志路径，仍返回可读字符串（C3） |
| FR-OVR-032 | MUST | 崩溃必须留下**结构化证据**（信号、出错地址、程序计数器、链接寄存器、栈指针、首参寄存器） | 崩溃后日志内出现形如 `CRASH sig=… si_addr=… pc=… lr=… sp=… r0=…` 的记录（规划 §5.7 / 硬约束：C6） |
| FR-OVR-033 | SHOULD | 崩溃记录必须可在**下一次启动**被读取，且以机器可读结构持久化 | 存在可读取的崩溃记录（⬜ 规划未实现 Phase 1） |
| FR-OVR-034 | MUST | 必须提供**端到端自检端点**，其输出是一次真实成功运行的证据 | 一条命令即可取回包含版本/平台/架构/启动参数/能力标志的 JSON（规划 §5.7） |
| FR-OVR-035 | MUST | 提供有界**日志环**供界面渲染（容量可配，默认 500 行） | 内存中可读回最近 N 行且上限生效（⬜ 规划未实现 Phase 1） |
| FR-OVR-036 | SHOULD | 提供状态变化的回调（含失败详情），使界面能展示阶段文案 | 存在状态回调接口（⬜ 规划未实现 Phase 1） |
| FR-OVR-037 | MUST NOT | 把「日志里没有某行」当作「没执行」；把「虚拟内存占用大」当作「运行时已起来」；把「点击看起来生效」当作「生效」 | 验收判据一律为**功能性事实**（端点输出/前后布局差异）（C6 / 规划 §5.7） |
| FR-OVR-038 | MUST | 调试用远程调试通道**只允许在调试构建开启**，发布构建必须关闭 | 发布构建中该开关不存在或强制关闭（规划 §5.7）⬜ 规划未实现 Phase 1 |

### 4.5 宿主能力桥（F5）

| 编号 | 级别 | 需求 | 可证伪的验收判据 |
|---|---|---|---|
| FR-OVR-040 | MUST | 提供 Node → 宿主的调用接口；**未注册的能力名必须返回结构化错误**，不得返回空值、不得崩溃 | 调用未注册能力得到可解析的错误对象（C2 / 规划 §5.4） |
| FR-OVR-041 | MUST | 调用载体必须不受「参数个数与类型」限制（序列化载体） | 单次调用可传复杂结构并经序列化往返（规划 §5.3） |
| FR-OVR-042 | MUST | 每次调用有**超时**（默认 10 s）与**载荷上限**（默认 8 MiB）；超限必须是结构化错误 | 超时/超限场景返回可解析错误而不是挂死（规划 §5.4）⬜ 规划未实现 Phase 2 |
| FR-OVR-043 | MUST | 跨线程调用必须线程安全，队列**有界**，溢出即报错而非静默丢弃 | 并发压测下无静默丢失（规划 §5.4）⬜ 规划未实现 Phase 2 |
| FR-OVR-044 | MUST NOT | 提供「宿主调用 Node 任意函数」的通用入口 | 方向 2 只有启动参数与关停两条（规划 §5.4） |
| FR-OVR-045 | MUST NOT | 在库内实现任何**具体能力**（权限、选择器、外链、通知） | 库只提供传输层；能力实现由消费方注册（规划 §6.1） |
| FR-OVR-046 | SHOULD | 选择器类能力只回传**沙箱内路径**，不回传文件内容 | 返回值形态为路径（大文件走 copy）（规划 §5.4） |

### 4.6 关停与失败态（F6）

| 编号 | 级别 | 需求 | 可证伪的验收判据 |
|---|---|---|---|
| FR-OVR-050 | MUST | 提供关停请求接口：触发脚本侧注册的收尾钩子并等待窗口期；**明确说明真正的停止只能是进程退出** | 接口存在且语义文档化（⬜ 规划未实现 Phase 1–2） |
| FR-OVR-051 | MUST | 失败态必须携带**阶段信息**与原始错误/信号，不得只报「失败」 | 失败态对象含阶段 + 原始原因（⬜ 规划未实现 Phase 1） |
| FR-OVR-052 | SHOULD | 运行时上线前必须验证「载荷未捕获异常会导致**整个宿主进程终止**」这一事实已被载荷侧兜底 | 载荷注册了未捕获异常与未处理拒绝的兜底并写独立日志通道（硬约束 ⑱）⚠️ 当前载荷只有顶层 `try/catch`，**捕获不到异步异常** |
| FR-OVR-053 | MUST | 运行时监听端口应由脚本侧**随机/先探测空闲**；宿主应用必须**单实例** | 端口冲突场景不再导致宿主进程终止（硬约束 ⑰）⚠️ 自检脚本固定端口属探针用途，非产品路径 |

### 4.7 运行时获取、校验与分发（规划 §5.8 / §7.5 / 附录 G）

| 编号 | 级别 | 需求 | 可证伪的验收判据 |
|---|---|---|---|
| FR-OVR-060 | MUST | 运行时产物必须**锁定**：版本、摘要、大小、来源、许可、门禁结论、真机验证记录 | 锁文件可 diff 审计；每一项都有值（✅ 已实测） |
| FR-OVR-061 | MUST | 运行时本体**不得**进入版本库，也**不得**随组件包发布 | 仓库与组件包内不存在该二进制（S10） |
| FR-OVR-062 | MUST | 投放必须**幂等**，且每一步都校验；任一校验不过即**硬失败**，绝不「就地找另一个凑合」 | 篡改 1 字节即失败；二次投放跳过拷贝（✅ 已实测，附录 G.4） |
| FR-OVR-063 | MUST | 校验必须包含「**不得是可执行文件形态**」这一项（有解释器段的产物必须被拒），因为该形态在进程内必然崩溃 | 构造一个带解释器段的产物 ⇒ 校验**失败**（✅ 已实测，门禁②） |
| FR-OVR-064 | MUST | 校验必须确认「运行时入口符号已导出」与「C++ 运行时的依赖已声明」 | 两者都能被检查出来（✅ 门禁④⑤） |
| FR-OVR-065 | MUST | 获取途径必须可离线完成（本地目录优先），联网只是兜底 | 断网环境下能完成投放（附录 G.3/G.6 路线 A） |
| FR-OVR-066 | SHOULD | 提供独立分发的签名能力；**不得**把它当作进程内加载的前提 | 签名校验可按内容验真；进程内加载不依赖它（G5 / 规划 §D.6）⬜ 独立分发场景的端到端验收未做 |
| FR-OVR-067 | MUST | 版本策略：组件包版本与运行时版本矩阵固化在锁文件里，README 呈现摘要 | 存在版本矩阵（✅ / 规划 §7.5） |
| FR-OVR-068 | MUST | 随包分发运行时，必须一并给出**第三方许可清单** | 交付物内存在许可清单（G4）⚠️ **当前缺口**（Phase 2/3） |

### 4.8 能力如实上报（C2）

| 编号 | 级别 | 需求 | 可证伪的验收判据 |
|---|---|---|---|
| FR-OVR-070 | MUST | 平台不支持的能力必须**上报为能力标志**，不得静默降级、不得返回空数组/假成功 | 自检输出中该能力有明确标志值（规划 §3.2） |
| FR-OVR-071 | SHOULD | 子进程能力只在运行时侧探测并上报；其产品用途由消费方决定 | 自检输出含子进程探测结论，库内无产品用途（规划 §4.5） |
| FR-OVR-072 | SHOULD | 完全隔离的运行时/线程能力必须可用（上游负载依赖），库不得额外隔离 | 多线程能力自检通过（规划 §2.4 / O3） |

## 5. 非功能需求

### 5.1 可观测性（NFR-OBS）

| 编号 | 需求 | 判据 |
|---|---|---|
| NFR-OBS-001 | 任何新增能力在落地前，必须回答「**怎么在真机上看见它**」 | 每个能力条目带一条真机可执行的观测命令（C6） |
| NFR-OBS-002 | 观测点必须在**应用域**（沙箱内日志外部读不到） | 取证通道为应用内端点或应用内读回，不依赖外部读沙箱文件（宪法 §三纪律 2） |
| NFR-OBS-003 | 失败必须在界面上留下**可截图**的文字，而不是白屏或静默 | 失败态存在可渲染文案（规划 §3.1 目标 7） |

### 5.2 体积（NFR-SIZE，规划附录 C）

| 编号 | 需求 | 判据 |
|---|---|---|
| NFR-SIZE-001 | 库给宿主包带来的增量（压缩后口径）**≈44 MB** | 复核方式：**查最终包内 `.so` 的压缩方式为 DEFLATE**，不是查磁盘（规划 §5.9）⚠️ 前提（压缩开关落在正确层级）当前未落 |
| NFR-SIZE-002 | 组件包本身**远小于**运行时本体（当前 ≈431 KB）且**不含**运行时 | 包内清单核对 ✅ |
| NFR-SIZE-003 | 原生库必须**压缩进包**（不得以未压缩方式进包） | 包内 `.so` 的压缩方式为 DEFLATE（`compress_type == 8`） |

### 5.3 合规（NFR-CMP，红线 G3/G4/G5/G11）

| 编号 | 需求 | 判据 |
|---|---|---|
| NFR-CMP-001 | 包内**不得**含第三方浏览器内核 | 包内文件清单只含运行时 + 引导件 + 脚本（G3 ✅） |
| NFR-CMP-002 | 第三方许可清单必须随包 | 交付物内存在清单（G4）⚠️ 缺口 |
| NFR-CMP-003 | 原生库的合规按「**已在包内**」与「**独立分发**」两种场景分别成立；前者不要求逐件签名标记 | 进程内加载成功且系统日志中无签名拒绝记录（G5 ✅ 已实测，规划 §D.6/§D.9） |
| NFR-CMP-004 | **不得**包含绕过平台代码签名 / 可执行内存控制的组件；该类技术只允许存在于设计文档与本机验证，与发布分支物理隔离 | 发布物与发布分支中不存在该实现（G11）⚠️ 高风险项 R23，须持续把守 |
| NFR-CMP-005 | 库不得引入渲染语义（不得触发「未使用系统 Web 组件」类驳回） | 库内无窗口/页面/浏览器语义（G3 库侧口径） |

### 5.4 供应链（NFR-SC，规划 §5.8 / 附录 G / R8/R20）

| 编号 | 需求 | 判据 |
|---|---|---|
| NFR-SC-001 | 引入的二进制必须**锁定来源 + 摘要 + 许可**，并能回答「验过没有」 | 锁文件含来源、摘要、许可、验证日期与验证设备 ✅ |
| NFR-SC-002 | 库只依赖运行时的 **ELF 属性与入口符号**，不依赖任何特定构建来源 ⇒ 产物可随时替换 | 换一行锁文件即可换版本；引导件不需重编（C7） |
| NFR-SC-003 | 禁止引入无法复现的黑盒二进制而不登记 | 每条运行时记录都有 `verifiedOn`/`verifiedDevice`/`verifiedNotes`（R8 显式登记） |
| NFR-SC-004 | 不得对上游/产物打补丁；能用现成机制（环境变量、启动参数、同名顶替、ELF 属性）解决的都不打补丁；必须打的补丁要幂等、可反向 | 无补丁即满足；有补丁则条件齐备（C7） |
| NFR-SC-005 | 只允许使用**可校验的公开获取路径**（本地目录 → 显式来源 → 镜像 → 上游） | 投放工具的三级优先级与失败信息 ✅ |

### 5.5 性能与行为基线（NFR-PERF，规划 §D.8/§D.10）

| 编号 | 需求 | 判据 |
|---|---|---|
| NFR-PERF-001 | 启用平台可执行内存权限时，WebAssembly 必须**可用且可校验** | 自检输出 `wasm.validate = true` ✅（规划 §D.10） |
| NFR-PERF-002 | 禁用即时编译时，必须**如实**表现为 WebAssembly 不可用，且性能显著下降（不得伪装可用） | 自检输出 `wasm.validate = false` 且热循环约为启用时的 7–10 倍耗时 ✅ |
| NFR-PERF-003 | 宿主载荷的运行期 WebAssembly 依赖是**权限的刚性动机**：禁用即时编译**不能**作为产品路径 | 权限缺失时启动即以信号崩溃，可复现 ✅（规划 §D.8） |
| NFR-PERF-004 | 首启代价必须可观测（就绪幂等命中 / 首次解包耗时可见） | 就绪耗时可从日志读出（⬜ Phase 1） |
| NFR-PERF-005 | 启动不得让宿主界面输入阻塞 | 无输入阻塞记录（NFR-OBS 同上） |

### 5.6 可靠性/可维护性（NFR-REL）

| 编号 | 需求 | 判据 |
|---|---|---|
| NFR-REL-001 | 接口面越小越稳：公共类型即对外契约，改动即破坏性变更，必须提版本 | 类型文件头声明契约属性；版本记录可查（S3） |
| NFR-REL-002 | 对外只暴露一个出口；新增公共符号必须同时更新出口与类型契约 | 出口清单与类型契约一致（S2） |
| NFR-REL-003 | 接口语言不得使用动态类型（不得出现任意类型/未知类型），原生模块只经类型声明接入 | 编译期严格模式通过（S1） |
| NFR-REL-004 | 信号上下文内禁止使用标准 IO 输出到标准流；只允许裸文件系统调用 | 崩溃路径只写文件（`open`/`write`/`close`）；格式化仅允许**栈上、无锁、无分配**（`snprintf` 口径待确认）（S5）⚠️ 见 §7 |
| NFR-REL-005 | 提交物中不得出现任何密钥/证书材料 | 仓库内无签名材料（⚠️ 当前工作区有一处未提交的越界，见 §7） |
