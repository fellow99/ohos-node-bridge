## 1. 模块概述

### 1.1 目的：本模块解决的问题

| # | 要取代的旧壳事实 | 依据 | 本模块的答案 |
|---|---|---|---|
| 1 | 旧壳唯一可用的能力通道是运行时的 `systemPreferences.callArkTSFunction`，**最多 3 个参数、只接受原始类型** —— 无法表达对象 / 数组 / 多字段能力 | ✅ §5.3 对照段；🔶 `pi-desktop-hos/src-main/main.js:370`（「明确不采用」） | 调用名与入参放进**一个语言中立的可序列化载荷**；不依赖参数个数与原始类型种类 |
| 2 | 旧壳把「能力未注册」变成**崩溃**：壳侧无条件调 `ExternalWeb.Open`，ArkTS 侧从未注册，适配器 `GetJSFunction … failed` 后解引用空指针 ⇒ 整进程 `SIGSEGV` | 🔶 风险 **R15**（`pi-desktop-hos/docs/工程规划.md:869`；现场注释 `pi-desktop-hos/src-main/main.js:1085-1087`） | 未注册的名字 ⇒ **结构化错误 + 日志**，绝不崩溃、绝不静默返回空（§5.4 失败语义；宪法 C2） |
| 3 | 旧壳的能力调用是**同步直调**，本形态下 Node 跑在独立 pthread，直调会跨线程触碰 ArkTS 对象 | ⚠️ `HostBridge.ets:8` 文件头自述 | Node 线程的调用必须**入队**并由 ArkTS 主线程执行（§5.4 方向 1；§5.2 线程模型） |
| 4 | 旧壳调用没有超时与载荷上限，挂住的调用会把上层永久卡住 | 🔶 §5.3 明确「**明确超时**（默认 10 s）」；🔶 `pi-desktop-hos/src-main/main.js:371-372`（`requestDirectoryPermission` 实测不 settle） | 每条调用有超时、有载荷上限、有并发与队列边界，失败一律结构化 |

### 1.2 范围 / 非范围

**在范围内**
- ArkTS 侧**注册表**语义：注册（含同名覆盖）、注销、枚举。
- **双向调用方向与边界**：Node → ArkTS 的调用通道；ArkTS → Node 只允许启动参数与关停两条（§5.4 方向 2）。
- 调用的**载体设计**（一个可序列化载荷）、**分发语义**、**永不抛异常的结构化错误返回**。
- **线程安全**（Node 线程不直接触碰 ArkTS 对象）、**不阻塞**、**超时**、**载荷上限**、**队列/并发有界**。
- **能力清单 v1 的名字与入参/出参契约**（冻结名字面；§5.4 能力清单行）。
- Node 侧**内置模块形态**：`require('@fellow99/node-bridge/host')`（§5.3）。

**不在范围内**（红线，C1）
- 每一个宿主能力的**实现**：权限预检 / 打开应用详情 / 文件与目录选择器 / 外链 / 通知 —— 属**消费方**（§6.1；§5.4）。
- 渲染、窗口、ArkWeb、鉴权、载荷内容、ACL 申报（§10 边界）。
- 平台无 PTY 之类的**能力缺口**本身不由本模块解决；本模块只保证「缺口能如实上报」（§5.10 先例明确放弃项）。
- 子进程（§0.3 非目标）。

## 3. 功能需求

> 编号 `FR-003-NNN` 连续、不可跳号。每条给出**现状标记**；⬜ 项一律属 Phase 2（§8 阶段计划）。

### 3.1 注册表

| 编号 | 需求 | 现状 |
|---|---|---|
| **FR-003-001** | 桥必须支持按**能力名**注册处理器；**同名注册必须覆盖**（后注册生效，不报错、不重复枚举、不保留旧处理器）。 | ✅ `HostBridge.ets:18-20` |
| **FR-003-002** | 桥必须支持**注销**一个能力名；注销未注册的名字**不得抛异常**，必须以可判定结果表达（如返回布尔）；注销后调用该名字必须落入 `FR-003-008` 的未注册错误。 | ⬜ 规划 §5.3 要求，代码缺 |
| **FR-003-003** | 桥必须能**枚举**当前已注册的能力名，供日志与自检使用；**空注册表必须返回空集合**（不是 `null`、不报错）；同一注册表状态下的枚举结果**不得包含重复项**。 | ✅ `HostBridge.ets:23-29` |
| **FR-003-004** | 注册表必须以**能力名为唯一键**，查找代价与注册项数量无关（诊断面与运行时都必须可扩展）。 | ✅ `Map` |

### 3.2 调用载体（取代 ≤3 参 / 仅原始类型）

| 编号 | 需求 | 现状 |
|---|---|---|
| **FR-003-005** | 一次调用必须由**能力名 + 一个语言中立的可序列化载荷**组成；**不得**要求调用方把参数按位置展开，**不得**对参数个数或原始类型种类设限。 | ✅ §5.3 对照段 |
| **FR-003-006** | 处理器返回的载荷必须与入参**同一种中立载体**（可序列化）；桥**不得**对成功结果做隐式重新包装或字段改写（成功路径的形状由能力实现自己决定）。 | ✅ `HostBridge.ets:41` 原样返回 |
| **FR-003-007** | 调用结果必须**无歧义可判成败**：成功与失败形状不得混淆，且失败必须携带**出错的能力名**与**错误类别**（不只是一段人读文本）。 | ⚠️ 现状失败带 `error`+`name`，但成功路径无类别标记，成败只能靠「未抛异常」判定；包裹形态的取舍见 `plan.md` §4.3 |
| **FR-003-008** | 未注册名字的调用必须返回**结构化错误**（`unregistered` + 该名字）：**禁止**返回空串、空集合、假成功（C2）。 | ✅ `HostBridge.ets:37-39` |
| **FR-003-009** | 处理器抛出的任何值（含非 `Error` 值、不可序列化值、循环引用对象）必须被转成 `handler-threw` 结构化错误并附可诊断细节；错误**不得穿透**、不得使桥进入不可用状态。 | ⚠️ 有骨架，但细节构造有真实缺陷（`plan.md` §6.2） |
| **FR-003-010** | 分发入口在**任何**输入下都不得向调用方抛出 —— 含名字非法/超长、入参非合法载荷、错误值无法序列化。 | ⚠️ 骨架意图如此，现状有逃逸路径（`plan.md` §6.2 缺陷 B/C） |
| **FR-003-011** | 返回内容必须是**合法可解析**的载荷：任何字段值都必须经过编码/转义，**不得**出现未转义的原始字符串拼接（否则名字含引号/换行即产生畸形载荷）。 | ⚠️ 现状拼接构造，见 `plan.md` §6.2 缺陷 A |
| **FR-003-012** | 处理器返回**非中立载体**（类型不符）时必须由桥转成结构化错误（如 `handler-invalid-return`），不得把非字符串值透给调用方。 | ⚠️ 现状不校验 |

### 3.3 方向、线程与阻塞语义

| 编号 | 需求 | 现状 |
|---|---|---|
| **FR-003-013** | 方向 1：Node 线程发起的调用必须由 **ArkTS 主线程**执行处理器；Node 线程**不得**在 ArkTS 上阻塞等待（除非调用方显式要求同步且自带超时）。 | ⬜ §5.4 方向 1 |
| **FR-003-014** | 方向 2 边界：ArkTS → Node **只有两条**通道（启动参数、关停钩子）；**不得**提供「ArkTS 调 Node 任意函数」的通用入口；应用语义走 HTTP/文件。 | ⬜ §5.4 方向 2 |
| **FR-003-015** | 桥的注册表与队列必须**线程安全**：任意线程触发的注册/注销/枚举/入队不得破坏内部一致性；处理器**只**在 ArkTS 主线程被调用。 | ⬜ §5.4 线程安全行 |
| **FR-003-016** | 处理器返回异步结果（Promise）必须被桥**等待**，并以同一超时兜底；调用方不得因能力实现内部异步而收不到结果。 | ⬜ 规划 §5.3 允许 `Promise<string>`，`Types.ets:49` 目前只声明同步 |

### 3.4 时间与容量边界

| 编号 | 需求 | 现状 |
|---|---|---|
| **FR-003-017** | 每条调用必须有**超时**（规划默认 **10 s**，以规划为准）；超时必须返回结构化 `timeout` 错误，**不得**无限等待，也不得同一调用返回两次。 | ⬜ 代码注释 30 s 与规划冲突 |
| **FR-003-018** | 单次载荷必须 ≤ **`capBytes`（默认 8 MiB，可配）**，对入参与出参**都**适用；超限必须在**执行/入队之前**被结构化拒绝（如 `too-large`），**不得截断、不得静默丢弃**。 | ⬜ §5.3 / §5.4 |
| **FR-003-019** | 待执行队列必须**有界**；溢出必须返回结构化 `queue-full`，**不得**丢请求、不得让队列无限增长。 | ⬜ §5.4 线程安全行 |
| **FR-003-020** | 在途并发数必须有可配上限；达到上限的调用按 `FR-003-019` 处置。 | ⬜ |
| **FR-003-021** | 涉及文件的调用**只回传沙箱内的绝对路径，不回传内容**（大文件由调用方自行读取/复制）；路径必须是绝对路径（不依赖工作目录）。 | ⬜ §5.4 参数上限行；S4 |

## 4. 关键实体

| 实体 | 说明 | 关键属性 | 现状 |
|---|---|---|---|
| **注册表项**（RegistryEntry） | 一个能力名到处理器的绑定；同名注册替换旧项 | `name`（键，非空）· `handler`（入参/出参均为中立载体）· 绑定时刻（用于诊断「何时被覆盖」） | ✅ `HostBridge.ets:15` |
| **调用请求**（InvokeRequest） | 一次跨线程调用的全部信息；在 Node 侧产生、在 ArkTS 主线程被消费 | `name` · `args`（中立载体）· `deadline`（由超时算出）· `origin`（发起线程） | ⚠️ 现状只有 `(name, argsJson)` 两个同步参数，无 deadline / origin |
| **调用结果**（InvokeResult） | 成功时返回的载体：**由能力实现自己给出**，桥不重写 | 由能力 schema 决定（如 `paths[]`、`opened`） | ✅ 原样返回 |
| **错误形态**（FailureShape） | 失败时由桥构造的结构化结果；判定面稳定 | `ok=false` · `error`（类别枚举）· `name` · `detail`（已编码的可诊断细节） | ✅ 骨架（三类）／⬜ 补齐类别集合 |
| **能力名**（CapabilityName） | 能力清单 v1 的保留名，是注册表的键空间与契约入口 | 见 §4.5 的 8 项；每项含方向与超时类别 | ⬜ 无任何实现 |
| **节点侧桥对象**（`host`） | Node 脚本看到的入口对象 | `invoke(name, args) → Promise` · `handle(name, fn)` · `list()` | ⬜ |

|---|---|---|
| **AS-003-01** | **未注册名调用**：注册表为空／某名字未注册时调用它 | 返回可解析的结构化失败，类别为「未注册」且**带上被调用的名字**；进程不崩溃；该事件在诊断面（hilog/日志）可见。依据 🔶 R15（旧壳在此崩进程） |
| **AS-003-02** | **处理器抛错**：已注册处理器 `throw new Error('boom')` | 返回 `handler-threw` 结构化失败（含名字与细节）；桥仍可用 —— **紧接着**再调一次同一名字仍能正常工作 |
| **AS-003-03** | **同名覆盖**：`register('a', h1)` 后 `register('a', h2)` | `list()` 中 `'a'` **只出现一次**；调用 `'a'` 走 `h2`；无异常 |
| **AS-003-04** | **Node 线程发起的调用**：Node 线程 `invoke` 一个会返回固定结果的处理器 | 处理器在 **ArkTS 主线程**执行（诊断可证）；Node 线程在等待期间**不被 ArkTS 阻塞**（主线程可继续处理其它事件）；结果正确回到 Node 侧 |
| **AS-003-05** | **超时**：处理器永不返回 / 返回一个永不 settle 的异步结果 | 在超时（默认 10 s，可配）后返回结构化 `timeout`；该调用**只**结算一次；桥仍可服务后续调用 |
| **AS-003-06** | **超过载荷上限**：提交大于 `capBytes` 的载荷 | 立即返回结构化 `too-large`；**不执行**处理器、不截断、不静默丢弃；上限对出参同样生效 |
| **AS-003-07** | **大文件选择器**：`fs.pickFiles` 选中一个远超上限的文件 | 结果只含**沙箱内绝对路径**，不含文件内容；调用方按路径自己读 |
| **AS-003-08** | **空注册表 `list()`** | 返回**空集合**（长度为 0 的字符串数组），不返回 `null`、不抛异常 |
| **AS-003-09** | **名字含特殊字符**（引号 / 反斜杠 / 换行 / 控制字符）时调用未注册名 | 返回值仍是**合法可解析**载荷，名字字段与原始名字逐字符一致（回归 `plan.md` §6.2 缺陷 A） |
| **AS-003-10** | **处理器抛不可序列化值**：`throw undefined` / 抛循环引用对象 | 返回值是合法可解析的 `handler-threw` 失败，**分发入口不抛异常**（回归缺陷 B/C） |
| **AS-003-11** | **队列溢出**：并发提交数超过队列/并发上限 | 被拒的调用拿到结构化 `queue-full`；已接受的调用正常完成；没有调用被静默丢弃 |
| **AS-003-12** | **双通道日志**：调用 `log.hilog` 且同时触发一次未注册调用 | 两条信息都在 hilog（域 `0xD0033`，`Logger.ets:4`）**与**应用日志文件中可见（C6 / S9） |
| **AS-003-13** | **方向 2 边界**：尝试用桥做「ArkTS 调 Node 任意函数」 | 该入口**不存在**（API 面上无可达之处）；ArkTS 侧只有启动参数与关停两条通道（§5.4 方向 2） |
| **AS-003-14** | **注销**：注册 → `unregister` → 调用 | 注销返回可判定结果；随后调用落入 AS-003-01 的未注册失败；再注册可复活 |

## 7. 假设与约束

| # | 假设 / 约束 | 依据 |
|---|---|---|
| A-003-01 | **异步方法必须走异步入口**，否则会**永久阻塞 Node 线程** —— 这是设计纪律，不是可选优化 | 🔶 §5.3 末段（照抄 notes 警告） |

| A-003-06 | 🔶 沿用的结论不得作为对外承诺：桥的线程安全形态必须在真机上验证一次（Phase 2 出口判据） | 宪法 §三 纪律 1 |
